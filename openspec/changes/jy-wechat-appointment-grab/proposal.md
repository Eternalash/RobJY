## Why

上海第九人民医院微信公众号（齐脉 H5：`h5.shqmxx.com`）门诊号源每日 7:30 放号，人工操作链路长（登录 → 预约须知 → 院区/科室/医师 → 日期时段 → 就诊人 → 验证码），难以及时抢到目标科室号源。需要一套可配置的自动化抢号能力，按既定优先级完成预约闭环。

## What Changes

- 新增面向九院微信公众号 H5 的抢号工具（CLI/脚本），覆盖从模拟登录到预约提交的完整链路。
- 支持模拟登录并维持会话（微信授权态/Cookie/Token），可复用或刷新。
- 实现门诊预约流程自动化：入口进入 → 预约须知点「是」→「我知道了」→ 院区/科室选择 → 医师与日期筛选 → 时段确认 → 就诊人确认 → 验证码填写 → 提交预约。
- 固化选择策略：院区优先南部院区，其次高科园区；医师优先主任医师，其次副主任医师。
- 支持每日 7:30 放号窗口的定时启动、轮询重试与失败可观测日志。
- 通过配置指定目标科室、就诊人、放号时间等，避免硬编码业务参数。

## Capabilities

### New Capabilities

- `h5-session-auth`: 九院齐脉 H5 模拟登录、会话持久化与失效重登
- `outpatient-booking-flow`: 门诊预约端到端流程（须知确认、科室进入、日期/时段预约、就诊人确认、验证码提交）
- `selection-priority`: 院区与医师职称优先级策略及可约号源筛选
- `release-scheduler`: 7:30 放号调度、轮询抢号与重试/告警

### Modified Capabilities

- （无）当前 `openspec/specs/` 为空，本变更为首批能力引入。

## Impact

- **代码**：新建抢号工具工程（建议 Python + 浏览器自动化或 HTTP 客户端），含配置、流程编排、策略与调度模块；仓库目前几乎为空（仅 README）。
- **外部系统**：依赖齐脉 H5（`h5.shqmxx.com`，CustomerId=94）及微信公众号授权态；接口/页面结构变更会导致选择器或接口适配成本。
- **依赖**：可能引入 Playwright/Selenium、HTTP 客户端、定时调度、验证码识别（人工输入或 OCR/打码服务，按实现选型）。
- **合规风险**：自动化预约可能违反医院/微信服务条款；仅限本人合法就诊用途，需可配置人工确认点（验证码、最终提交确认），不得用于倒号或批量占用。
- **运维**：需稳定网络与准确系统时钟；放号瞬时并发高，需控制请求频率并记录审计日志。
